# 対戦テトリス

友達と2〜4人で遊べるテトリスです。**ウェブアプリなのでインストール不要**。それぞれのスマホでURLを開くだけで、Wi-Fi がなくても（携帯の電波だけで）離れた場所の友達と対戦できます。

おじゃまブロック、T-Spin、REN（連続消し）、Back-to-Back、パーフェクトクリアに対応。ミノの出る順番は全員で完全に同じなので、運ではなく腕で勝負が決まります。

## 遊びかた

1. 全員がスマホでゲームのURLを開く
2. ひとりが名前を入れて「部屋を作る」を押す → 数字4桁のコードが出る
3. そのコードをみんなに伝える。ほかの人はコードを入れて「参加する」
4. 全員そろったら、部屋を作った人が「はじめる」を押すと3カウントで対戦開始

3人以上のときは、おじゃまブロックは**自分を最後にやっつけた相手に送り返します**（しかえし）。まだ誰にもやられていないうちは、生きている相手からランダムに選びます。人数が多いほど1回に送る段数はひかえめになります（3人で4分の3、4人で5分の3）。倒れた人はそのまま観戦にまわり、最後に残った1人が勝ちです。

ブラウザのメニューから「ホーム画面に追加」しておくと、次からはアイコンをタップするだけで開けます。

## 操作

画面下の左側が移動、右側が回転です。

`◀ ▶` で左右移動（長押しで連続移動）、`▼` でソフトドロップ、`↺ ↻` で左右回転、`HOLD` でミノを1つ預けて温存できます。一番下の広いボタンがハードドロップです。

盤面の左にあるオレンジ色のバーは、これから自分にせり上がってくるおじゃまの量です。赤くなったら危険信号なので、早めに消して相殺してください。

## おじゃまブロックの火力

| 消し方 | 送る段数 |
| --- | --- |
| シングル（1列） | 0 |
| ダブル（2列） | 1 |
| トリプル（3列） | 2 |
| テトリス（4列） | 4 |
| T-Spin シングル | 2 |
| T-Spin ダブル | 4 |
| T-Spin トリプル | 6 |

これに加えて、テトリスや T-Spin を連続で決めると Back-to-Back で +1、連続でラインを消すと REN ボーナスが最大 +5、全消しを決めると +10 されます。

相手から飛んできたおじゃまは、自分が消したぶんで打ち消せます。せり上がるのはライン消去できなかったターンだけなので、攻められているときは何か消せば耐えられます。1回にせり上がるのは最大8段までです。

## 公開するまで（最初の一度だけ）

### 1. GitHub にこのフォルダを置く

[github.com](https://github.com) で新しいリポジトリ（例: `tetris-versus`）を作り、このフォルダをまるごとプッシュします。

### 2. サーバーを Render で公開する

対戦の中継役サーバーが、どこか一箇所で動いている必要があります。[render.com](https://render.com) の無料プランで十分です。

GitHub アカウントで Render にログインし、**New → Blueprint** からこのリポジトリを選びます。同梱の `render.yaml` を読んで自動で設定してくれます。

手動で作る場合は **New → Web Service** で次のように設定します。

| 項目 | 値 |
| --- | --- |
| Root Directory | `server` |
| Build Command | `npm install` |
| Start Command | `npm start` |
| Instance Type | Free |

デプロイが終わると `https://〇〇〇.onrender.com` というアドレスが発行されます。ブラウザで開いて `{"ok":true,...}` と出れば成功です。

### 3. サーバーのアドレスをアプリに教える

`web/src/config.ts` を開き、`DEFAULT_SERVER_URL` を書き換えます。**`https://` ではなく `wss://` にする**のがポイントです。

```ts
export const DEFAULT_SERVER_URL = 'wss://〇〇〇.onrender.com';
```

書き換えたら、ビルドし直して `docs/app.js` を更新します。

```bash
npm install
npm run build:web
```

（書き換えなくても、ゲームのホーム画面の「サーバー設定」に入力すれば遊べます。）

### 4. GitHub Pages でゲーム本体を公開する

リポジトリの **Settings → Pages** を開き、次のように設定します。

| 項目 | 値 |
| --- | --- |
| Source | Deploy from a branch |
| Branch | `main` |
| Folder | `/docs` |

保存すると数分で `https://ユーザー名.github.io/tetris-versus/` が使えるようになります。これが二人で開くURLです。

## 気をつけること

Render の無料プランは15分アクセスがないと眠ります。次に繋いだとき最初の1分ほど「サーバーに接続中…」のまま待たされますが、故障ではありません。先に部屋を作る方が少し早めに開いておくとスムーズです。

GitHub Pages は `https://` で配信されるため、サーバーは必ず `wss://`（`ws://` ではない）である必要があります。

## 中身

| フォルダ | 役割 |
| --- | --- |
| `web/src/` | ウェブ版の本体（TypeScript） |
| `docs/` | 公開されるファイル一式。`app.js` は `web/src/` をビルドしたもの |
| `server/` | 部屋のマッチングと中継をするサーバー |
| `app/src/engine/` | テトリスの計算ロジック（ウェブ版もこれを使っています） |
| `app/` | 以前作った Expo 版アプリ。今は使いません |
| `tools/` | 通し動作を確認するテスト |

ゲームの計算は各端末で行われ、サーバーは部屋の管理とデータの受け渡しだけを担当します。

## 開発メモ

```bash
npm install
npm test            # エンジン・サーバー・通し対戦・ウェブ版をまとめて検証
npm run build:web   # web/src → docs/app.js
npm run server      # ローカルでサーバーを起動（ws://localhost:8080）
npm run preview:bgm # BGMを bgm-preview.wav に書き出して耳で確かめる
```

ローカルのサーバーに繋いで試すときは、URLの後ろに `?server=ws://localhost:8080` を付けて開きます。パソコンのキーボード（矢印キー・Z/X・Space・Shift）でも操作できます。

回転は SRS（ワールドルール）準拠、ミノの供給は7バッグ方式です。同じシードから同じ順番を生成するので、サーバーは対戦開始時にシードを1つ配るだけで両者の公平性が保たれます。T-Spin の判定は3隅ルールで、直前の操作が回転だった場合のみ成立します。

## うまくいかないとき

**「サーバーに接続できません」と出る** — Render の無料プランがスリープしている可能性があります。ブラウザでサーバーのアドレス（`https://〇〇〇.onrender.com`）を開いて起こしてから、もう一度試してください。アドレスが `wss://` で始まっているかも確認してください。

**部屋コードを入れても「見つかりません」と出る** — 二人が別々のサーバーを見ている可能性があります。両方の「サーバー設定」が同じアドレスになっているか確認してください。

**片方の端末から音が出ない** — ホーム画面の「音を鳴らしてみる」を押してください。ここで鳴らなければ、iPhone なら本体横のマナーモードのスイッチと音量を確かめます。ゲーム中の「音 オン／オフ」は端末ごとに覚えているので、以前オフにしたままになっていることもあります。
